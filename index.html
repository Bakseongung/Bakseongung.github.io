쑥쑥찰칵 1억 스토리지 비용 절감 프로젝트

성장앨범 미디어 서비스의 클라우드 Object Storage를 Kubernetes 기반 Rook-Ceph로 대체해 저장 효율·운영 안정성·비용 효율성을 검증 · 인프라/스토리지, DevSecOps, FinOps, AI ChatOps 담당

Kubernetes · Rook-Ceph (EC 2+1 · RGW · RBD) · PostgreSQL · Go · FFmpeg · GitLab CI · ArgoCD · Prometheus · Grafana · Loki · Kepler · Cloudflare CDN · Gemini

01. 프로젝트 개요

01-1. 서비스 분석

벤치마킹 대상쑥쑥찰칵 · 구글 플레이스토어 육아 카테고리 대표 서비스, 사용자 약 100만 명 규모의 성장앨범 사진·영상 관리 서비스

서비스 특징

  • 자녀 성장 과정을 사진·영상으로 기록하고 공유하는 성장앨범 서비스
  • 사용자가 업로드한 사진·영상 데이터를 장기간 보관하는 데이터 중심 서비스
  • 일반 화질 기반 저장 및 공유 기능 제공
  • 사진·영상 데이터가 계속 늘어나 스토리지 용량과 운영 비용이 함께 증가하는 구조

분석 결과

  • 성장 기록은 장기 보관 가치가 높아 시간이 지날수록 저장 용량이 계속 증가한다.
  • 사진·영상 데이터 증가에 따라 스토리지 비용과 네트워크 트래픽 비용이 함께 증가한다.
  • 대규모 성장앨범 서비스에서는 애플리케이션 기능보다 안정적인 저장 구조와 비용 효율적인 스토리지 운영 전략이 핵심이다.

01-2. 문제 정의

  • 저장 비용 사진·영상 데이터 증가에 따른 Object Storage 저장 비용 증가
  • 트래픽 비용 사용자 조회·다운로드 과정에서 발생하는 아웃바운드 트래픽 비용 증가
  • 장기 보관 부담 장기 보관 데이터 증가에 따른 지속적인 운영 비용 부담
  • 복제 오버헤드 데이터 보호를 위한 복제·백업 구조로 인한 추가 저장 공간 필요

기존 클라우드 Object Storage 구조를 분석하고, Kubernetes 환경에서 운영 가능한 Rook-Ceph 기반 클라우드 네이티브 스토리지를 설계해 저장 효율, 운영 안정성, 비용 효율성을 검증했다.

01-3. TCO 기반 비용 비교 및 기대 효과

성장앨범 서비스의 대규모 사진·영상 저장 환경을 가정해 클라우드 Object Storage와 Rook-Ceph 스토리지의 총소유비용(TCO)을 비교했다.

연간 기준AWS S3 StandardCloudflare R2Rook-Ceph 자체 운영
저장 비용약 2.7억 원약 1.8억 원하드웨어·전력 운영 비용 중심
데이터 전송 비용약 15억 원API 비용 중심내부 네트워크 기반 운영
운영 비용포함포함전력 및 관리 비용 발생
예상 총비용약 17~18억 원약 1.8억 원실습 환경 기준 전력비 중심 운영

※ Rook-Ceph 비용은 동일 규모 서비스를 실제 구축한 비용이 아니라, 저장 효율과 운영 구조 검증을 위한 자체 Kubernetes 실습 환경 기준으로 산정했다. 실제 대규모 서비스에서는 서버, 스토리지, 네트워크, 운영 인력을 포함한 별도의 TCO 분석이 필요하다.

기대 효과

  • 저장 효율 Erasure Coding(K=2, M=1)으로 데이터 보호 수준을 유지하면서 3복제 대비 저장 효율 향상 저장 효율 66.7% (3복제 33.3%)
  • 호환성 S3 호환 API(RadosGW)로 기존 애플리케이션 변경 최소화
  • 운영 자동화 Kubernetes Native Storage 기반의 확장성과 자동화 운영 환경 확보
  • TCO 예측 사진·영상 혼합 데이터셋으로 저장 용량 증가에 따른 비용 변화를 회귀분석해 PB급 환경의 TCO를 예측하고 스토리지 투자 의사결정 근거 제시 100TB → 1PB → 5PB → 10PB
